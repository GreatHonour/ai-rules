# 实现

读取同一日期目录的 `design.md`、`task.md`、`delivery.json` 和项目规则。

## 任务调度

1. 找出 `depends` 全部满足且状态为 `[ ]` 的任务；按依赖顺序串行执行，职责独立且写入范围不重叠时才并行。
2. 实现前确认任务边界和写入文件；超出范围、契约冲突或需要新业务决策时停止并报告。
3. 可自动化的单元、组件、API、契约、迁移和配置行为采用 TDD：先运行失败验证，再做最小实现，再确认通过。
4. 每个任务完成后运行适用的定向测试、类型检查、lint 或构建，并记录命令、结果、仓库、分支、提交和时间。
5. 只有实现和验证事实齐全时，才把任务标题从 `[ ]` 改为 `[x]`；失败或阻塞保持 `[ ]`，并在任务下方写明原因、已尝试方案和下一步。

TDD 是代码验证，不替代微信、真机、浏览器、跨仓库用户流程验收。全部普通任务完成后进入 `flow-v3-review`；`acceptance.json` 的集成验收任务不在本 Skill 中标记完成。
