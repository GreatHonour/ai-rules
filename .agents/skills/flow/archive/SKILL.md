# 流程归档

归档本次迭代的实现事实和有效经验。`log.md` 是功能演进史；`.docs/retro.md` 是待用户处理的经验候选池，不是规则库。

## 归档规则

1. 只记录已经实现或验证的事实，不补写未完成的想法。
2. 同一日期目录内，可将 review、E2E 或 bugfix 产生的实现级修正同步回 `design.md` 和 `task.md`；历史日期目录不得改写。
3. 核心方案发生变化时，写入新日期目录，不覆盖原设计。
4. `design.md`、`task.md` 和 `*-fix.md` 长期保留；`review.md` 和 `e2e-report.md` 是过程文件，执行阶段清理。
5. 真机或外部验证项不写入 `task.md`，但必须在归档摘要中说明是否阻塞发布。

## 更新 log.md

路径：`.docs/[文件名]/log.md`。按日期倒序追加，只记录功能变化、关键边界、结构决策和遗留事项，不写阶段流水账，也不复述其他产物。

```markdown
## 功能：[功能名]

### YYYY-MM-DD [首版/变更主题]
- 能力或变更：[对外行为]
- 关键逻辑：[重要规则或边界]
- 结构决策：[方案及原因]
- 影响面：[后续修改时填写]
- 遗留：[外部验证、占位资源或依赖]
```

没有内容的字段省略。纯重构、命名、注释和阶段完成信息不写入 `log.md`。

## 记录经验候选

读取 `.docs/retro.md`，仅在本次迭代有明确证据时按日期倒序追加；没有可靠经验时不写占位内容。

```markdown
## YYYY-MM-DD [文件名]

- [代码/流程/工具] [问题或观察]
  - 证据：[文件、产物章节或错误]
  - 影响：[实际后果]
  - 建议：[可能的处理方向]
```

- 代码、流程和工具经验全部只写入 `.docs/retro.md`。
- 不自动修改 Skill、规则或项目配置，不替用户判断经验是否应长期保留。
- 不做自动计数、归类、备份或清空；后续由用户自行处理。
- 需求特有的业务事实写入 `log.md`，不写入 `retro.md`。

## 执行

1. 读取本次迭代产物，确认普通任务与所需集成验证均已完成；若 E2E 被豁免，记录豁免依据。
2. 将本迭代已经发生的实现级修正同步回 `design.md`、`task.md`。
3. 更新 `log.md`（不存在则新建）；删除 `review.md` 和 `e2e-report.md`（若存在）。
4. 有明确经验候选时更新 `.docs/retro.md`。
5. 输出归档摘要，包括保留产物、任务状态、E2E 状态、遗留项、经验候选和发布状态。
6. 检查 Git 变更归属，只提交本次任务相关文件；测试与对应实现必须成对纳入，不提交用户或其他迭代的修改。

归档和提交完成后，工作流结束。
