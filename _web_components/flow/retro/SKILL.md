# 流程回顾 (Retrospective)

归档完成后，扫描本次迭代的流程卡点，输出改进建议追加到 `.docs/retro.md`。

## 规则

1. 反思流程不反思代码——代码问题归 code-quality.md（archive 已处理）
2. 卡点必须有建议，不允许只提问题不给方案
3. 改进建议标注 `[💡 可优化]`（本轮可安全修改 skill）或 `[📝 观察]`（案例不足先记录）
4. `[💡 可优化]` 必须写明改哪个 skill 的哪部分
5. 没问题就写"无明显卡点"，不硬凑
6. 先读历史 retro.md，避免重复提出相同建议
7. `[💡 可优化]` 必须在本轮更新对应 skill 并记录已落地；无法安全落地时降为 `[📝 观察]` 并说明缺少的证据
8. 同类观察重复出现两次时必须重新评估，不得继续原样追加

## 回顾维度

| 维度 | 检查什么 |
|------|----------|
| 边界遗漏 | brainstorm 阶段漏掉的边界是否导致后续返工 |
| 任务拆分 | 粒度是否均匀，是否有 task 间接口不匹配 |
| 实现阻塞 | 是否有 task 重试失败、并行策略不合理、E2E 问题本应单测拦住 |
| 流程效率 | 是否有冗余输出、反复返工、交接信息不完整 |

## 执行流程

```
1. 读取本次迭代所有产物 + 历史 retro.md
2. 按 4 个维度扫描卡点
3. 对每个卡点给出改进建议
4. 落地 `[💡 可优化]` 对应的 skill 修改
5. 追加到 .docs/retro.md 顶部（倒序），注明已落地项
```

## 输出格式

```markdown
## YYYY-MM-DD [需求名]

### 卡点

- [阶段] 问题描述
  - 影响：导致了什么后果
  - 建议：下次如何避免

### 流程改进

- [💡 已落地] 修改了哪个 skill 的哪部分，解决什么问题
- [📝 观察] 疑似问题，先记录待更多案例确认
```

无卡点时省略"卡点"和"流程改进"章节，写一句"本次流程执行顺畅，无明显卡点"即可。

## 执行

工作流终点，无下游。
