# 任务实现 (Implement)

读取 `.docs/[文件名]/[YYYY-MM-DD]/task.md`，按批次调度、逐一实现 `[ ]` 状态的 task。

## 前置：能力探测

执行前先判断运行环境是否支持派发 subagent：

- **支持** → 启用完整并行流程，规则 9-12 全部生效
- **不支持** → 退化模式：
  - 所有批次由主 agent 串行执行
  - 规则 9-12、subagent 启动包、批次表"是否并行"列全部忽略
  - 批次规划仍需产出（用于 depends 排序，避免乱序），"是否并行"列恒为否
  - 退化模式下的串行不视为违反规则 12

## 规则

### 单任务规则

1. 读再写：实现前先读 `AGENTS.md` 和相关现有代码，匹配项目风格
2. TDD 强制：先写测试（红灯）→ 再写实现（绿灯）→ 类型检查 + lint 通过 → 标记 `[x]`
3. 类型同测：写完实现代码后与单元测试一并跑 `vue-tsc --noEmit`，类型层无错误才算绿灯，禁止把类型错误留到 build 阶段
4. 测试环境预检：涉及 Vue 核心特性（Transition/Teleport/Suspense）时，先确认测试环境的 stub 行为（VueTestUtils 默认 stub `<Transition>`，会导致 after-enter/after-leave 等钩子不触发），必要时显式关闭 stub，避免黑盒试探
5. 不越界：严格按 task 验收条件实现，验收没写的不做
6. 零容忍：lint / 类型报错必须修复，不允许带错进入下一个 task
7. 设计问题上报：发现 design 有遗漏或矛盾时停下报告，不自行修改设计
8. 交付完整：task 中的组件文档和 Demo 必须在实现阶段完成，不留到 E2E 临时补建

### 并行专属规则

9. 文件白名单：subagent 只能读写分配的文件白名单，越界立即终止本 subagent
10. 单点写入：task.md 的状态位（`[ ]` → `[x]`）只由主 agent 更新，subagent 严禁修改 task.md
11. 失败隔离：批次内单个 subagent 失败不影响其他 subagent 的绿灯认定，但整批未全绿前不进入下一批
12. 禁止降级：在支持 subagent 的运行环境下，满足并行触发条件的批次必须并行，不得因"图省事"退回主 agent 串行（不支持 subagent 时本规则不生效）

## 执行流程

外层为批次调度循环，内层为单任务 TDD 循环。

```
外层：批次调度
1. 读取 task.md 全部 [ ] 任务；若全部 [x] → 报告"所有任务已完成"
2. 读取 design.md 理解接口和数据结构
3. 批次规划（Batch Planning）
   a. 根据 depends 字段构建依赖图
   b. 输出批次表（必须显式产出，不得跳过）：
      | 批次 | 任务ID | depends | 文件白名单 | 是否并行 |
4. 依批次顺序执行：
   a. 判断并行策略触发条件（前置探测为"不支持 subagent"时直接走串行分支）
      - 支持 subagent 且满足触发条件 → 派发 N 个 subagent，每个附带标准启动包，等待全部返回
      - 不支持 subagent 或不满足触发条件 → 主 agent 按内层 TDD 循环串行执行本批次
   b. 汇总验证：test + vue-tsc --noEmit + lint（跨任务全量验证，确认 subagent 各自绿灯后整合无冲突）
   c. 全绿 → 主 agent 批量将本批次 [ ] 改为 [x]
   d. 任一失败 → 只重试失败任务（走失败处理 2 次上限）
   e. 进入下一批次
5. 全部批次完成 → 进入 "收尾" 章节

内层：单任务 TDD（主 agent 或 subagent 均按此执行，仅输出结果，不写 task.md）
   a. 根据验收条件写测试 → 运行确认红灯
   b. 实现代码 → 运行确认绿灯
   c. 跑 `vue-tsc --noEmit` 确认类型无错误 + lint 通过 → 返回结果给外层
```

## 并行策略

### 触发条件（必须全部满足才并行）

- 当前批次 [ ] 任务数 ≥ 2
- 任务间无 depends 依赖（或 depends 目标已全部 [x]）
- 各任务文件白名单互不相交
- 单任务涉及 ≥ 2 个源文件，或包含独立的组件 / 工具函数交付（避免为小改动开 subagent）

任一条件不满足 → 串行执行本批次。

### depends 语义

- `depends: <taskId>`：等待指定任务 [x] 后再执行
- `depends: all`：等待前面所有任务 [x] 后再执行
- 无 `depends` 字段：视为独立任务，参与并行判定

### 调度规则

- 同一工作树中同一文件同一时刻只允许一个写入方
- 汇总验证完成前不拆分提交

（其他并行硬约束见"并行专属规则 9-12"，不再复述）

### subagent 启动包（标准模板）

每个 subagent 派发时必须携带以下上下文，避免其自行摸索：

```
- taskId：任务编号
- 验收条件：从 task.md 摘取的原文
- design 片段：design.md 中该任务相关的接口 / 数据结构
- 文件白名单：可读写的文件路径列表
- 约束引用：必须遵守规则 5（不越界）、规则 9（文件白名单）、规则 10（禁改 task.md）
- 返回契约：
  - 测试运行结果（红/绿）
  - vue-tsc 输出
  - lint 输出
  - 已改动文件列表
```

## 失败处理

```
测试不通过 → 分析原因 → 修复 → 重跑（第 1 次）
仍然失败   → 更深层分析 → 修复 → 重跑（第 2 次）
仍然失败   → 停止，报告：
  - task 编号和名称
  - 失败的测试和实际输出
  - 两次修复思路
  - 建议的下一步
```

重试上限 2 次，超过则需用户介入。

## 收尾

全部 task 完成且验证通过后，直接调用 `review/SKILL.md` 继续，无需等待用户确认。
