# 流程归档 (Archive)

E2E 验证完成后，更新迭代日志、清理过程草稿、提取经验规则、输出完成摘要。

log.md 的定位是**功能演进史**（面向未来开发者：这个功能做了什么、关键决策为什么这样定、后续怎么改的），不是阶段流水账。

## 规则

1. 本迭代内（同一日期目录下）允许将 review / e2e / bugfix 阶段产生的**实现级修正**同步回 design.md / task.md，保持产物内部自洽。跨迭代（新日期目录）历史 design/task 冻结，新变更走 log.md「后续修改」+ 新日期目录
2. 回更边界：只补/改**已发生的实现事实**（补边界、补 T 项、修正字段描述），不新增未做的设计想法、不改核心决策（如换方案）；改核心决策要走新迭代
3. review.md 是过程草稿，归档时抽净结论合并入 log.md 后**删除**；fix.md 是长期知识资产（含根因/复现/方案），**保留**，log.md 相关条目链回
4. 真机等线下验证项不写入 task、不阻塞归档，但完成摘要必须如实列出线下验证余项与发布阻塞状态，禁止声称全部完成

## 执行流程

```
1. 更新 log.md（按下方格式在顶部追加倒序；review 净结论从本迭代 review.md 抽取合并后，删除该 review.md；涉及 fix.md 的变更条目链回文件路径）
2. 同步回更 design.md / task.md（若 review/e2e/bugfix 有影响设计描述或任务清单的实现级修正；可在 design.md 底部加「本迭代内修订」小节列改动点）
3. 沉淀经验规则到 .agents/rules/code-quality.md（判断标准见下；新规则分配 CQ-<分类>-<序号> ID，稳定且不复用）
4. 输出完成摘要
```

### log.md 格式

首次迭代（新增功能）：

```markdown
## 功能：[功能名]

### YYYY-MM-DD 首版
- 能力：[一句话，这个功能能做什么]
- 关键逻辑：
  - [规则/边界/映射等，回来查阅时最想知道的]
- 结构决策：
  - [模块拆分/组件提升/公共化等，写清"为什么这样定"]
- 遗留：
  - [占位资源、真机验证项、外部依赖等]
- review 净结论：🔴N 🟡N | 修复 N / 撤回 N（原因）/ 跳过 N / 延后 N（去向）
```

后续修改（同一功能再迭代）：

```markdown
### YYYY-MM-DD [变更主题]
- 变更点：[做了什么]
- 影响面：[改到哪些模块/接口/测试]
- 原因：[为什么改，关联需求或 bug]
- review 净结论：🔴N 🟡N | 修复 N / 撤回 N（原因）/ ...
```

写入判断：
- 值得写：变更了对外行为、新增/调整边界、修改了结构决策、遗留项变化、review 有撤回或延后
- 不值得写：单纯的重构、命名调整、注释补充（这些走 git log 就够）；「brainstorm 完成 / plans 完成 / implement 完成」这类阶段元信息也不写
- 不复述 design.md / e2e-report.md 已有内容，只写决策与约束

### 经验规则判断标准

写入（满足任一）：
- 跨需求都会遇到的通用陷阱
- 设计阶段就可以避免的遗漏
- 实现阶段的通用模式错误

不写入：
- 需求特有的业务逻辑
- 已被 lint、TypeScript 或其他项目规则覆盖的问题
- 同类规则已存在于 code-quality.md（禁止重复追加）
- 不确定是否通用的：先留在本次归档产物中观察，不进 code-quality.md

措辞要求：必须可操作。写「表单提交前必须 trim」而不是「注意输入处理」。

### 完成摘要格式

```
✅ [需求名] 归档完成

设计文档：.docs/[文件名]/[YYYY-MM-DD]/design.md（已同步本迭代内修订 / 无修订）
任务列表：.docs/[文件名]/[YYYY-MM-DD]/task.md（N/M 已完成；无余项或列出外部验证余项）
E2E 报告：.docs/[文件名]/[YYYY-MM-DD]/e2e-report.md
Bugfix 记录：[YYYY-MM-DD]/xxx-fix.md（如有，保留）
迭代日志：已更新（review 净结论已合并；review.md 已删除）
经验规则：新增 N 条 / 无新增
发布状态：可发布 / 被 [外部验证项] 阻塞
```

## 提交
归档成功后, 自动 `git` 提交当前组件相关的文件，不要 `diff` 内容；

## 执行

提交完成后，直接调用 `retro/SKILL.md` 继续。
