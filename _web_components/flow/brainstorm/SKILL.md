# 头脑风暴 (将想法转化为设计)

用户描述需求 → 输出 2-3 个方案 → 用户选定 → 列出边界问题带建议值 → 用户确认 → 产出选定方案 + 边界清单 → 直接调用 plans skill。

## 规则

1. 遇到歧义自行假设并在方案中标明，并询问客户
2. 不输出代码：只讨论方案、边界和交互
3. 方案数量：简单需求 2 个，复杂 3 个，不只给 1 个
4. 优缺点必须是实质性差异，不写"实现简单"之类空话
5. 边界由模型主动穷举，每条带建议值 + 理由，用户负责确认

## 第一步：输出方案

```markdown
## 方案 A：[方案名]

**核心思路**：[一句话]

**实现路径**：
1. [步骤]
2. [步骤]

**优点**：[1-2 条]
**缺点**：[1-2 条]

## 方案 B：[方案名]

...

---
**推荐**：方案 X，原因：[一句话]

请选择方案（A / B / C），或说明调整方向。
```

## 第二步：边界确认

用户选定方案后，穷举边界问题。覆盖面：交互行为、数据边界、异常处理、兼容性、性能、可访问性。

涉及浮层、动画、计时任务或动态挂载时，固定检查以下移动端边界：

- 浏览器计时器上限及超长时长的分段调度
- `visualViewport` 不可用、尺寸变化及布局视口 fallback
- 动态实例、全局 Host、计时器和窗口监听的销毁时机

```markdown
已选方案 X，需要确认的边界：

- [ ] [问题 1]？（建议：[值]，理由：[一句话]）
- [ ] [问题 2]？（建议：[值]，理由：[一句话]）
```

用户回复方式：
- "都用建议值" → 全部采纳
- "1、3 用建议值，2 改成 xxx" → 部分修改
- "再加上 [新边界]" → 补充后更新列表

## 第三步：输出产物

```markdown
## 选定方案

**方案名**：[方案名]
**核心思路**：[一句话]

**实现路径**：
1. [步骤]
2. [步骤]

## 已确认边界

- ✅ [边界 1]：[确认值]
- ✅ [边界 2]：[确认值]
- ❌ [边界 3]：不需要（理由）
```
