# flow-plan-review 任务列表

## Skill 能力

#### [x] T1: 建立计划追踪审查 skill
depends: 无

- 存在已确认决策源、`design.md` 和 `task.md` → 重建“决策 → 设计 → 任务”三向追踪映射。
- 术语存在会改变契约的多种解释，或关键场景存在两种合理结果 → 无法从决策源确定时列为阻塞。
- 输入缺失或属于未经过 plans 的 bugfix → 停止审查并说明原因，不降级执行。
- 追踪完整且无问题 → 只输出简短通过摘要。
- 发现有证据的问题 → 按“阻塞”和“建议”批量输出受影响链路、影响与推荐修改。
- 用户确认修改 → 修正原有计划文档并重新执行完整审查。
- 需要新增业务决策或阻塞项未解决 → 返回上游或停止，不进入实现。
- 审查通过且用户未要求停止 → 自动调用 `flow-implement`。

## 流程集成

#### [x] T2: 将计划审查接入 flow-plans
depends: T1

- `flow-plans` 完成 `design.md` 和 `task.md` → 自动调用 `/flow-plan-review`。
- 接入新审查流程 → 不再将 `grill-with-docs` 或直接实施作为同级出口。
- `flow-plan-review` 接管审查问题闭环和进入实现的路由 → `flow-plans` 不重复询问。

## 验证

#### [ ] T3: 验证 skill 结构与关键场景
depends: T1, T2

- 检查 skill 元数据和内部引用 → 名称、描述、路径及下游路由一致。
- 完整计划、决策断链、术语歧义、场景结果未定义、任务越界和前置条件缺失场景 → 输出分别符合通过、阻塞和拒绝规则。
- 对照 `flow-review` 职责 → 不包含代码实现与测试结果审查。
