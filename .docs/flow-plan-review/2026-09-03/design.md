# flow-plan-review 设计文档

## 目标与范围

- 目标：在 `flow-plans` 生成计划后、实施前，验证已确认决策是否完整且一致地映射到 `design.md` 和 `task.md`。
- 成功标准：每项原始决策均可追踪到设计与任务，任务不反向新增范围；阻塞问题清零后自动进入 `flow-implement`。
- 职责边界：负责计划产物的语义一致性审查与确认后的文档修正；不审查实现代码、测试实现或代码质量。

## 现状与约束

- `flow-plans` 当前生成 `design.md` 和 `task.md` 后，由用户选择 `grill-with-docs`、直接实施或停止。
- `flow-review` 在实现完成后依据 `git diff`、设计、任务和测试审查代码，不承担实施前的计划审查。
- `flow-bugfix` 不生成 `design.md` 和 `task.md`，不进入本流程。
- 审查结论只在对话中输出，不创建 `plan-review.md` 或其他过程文件。
- `flow-plan-review` 不依赖 `grill-with-docs`、`domain-modeling` 或 `grilling`。

## 技术方案

### 模块与职责

```text
flow-plans
├── 生成 design.md
├── 生成 task.md
└── 自动调用 flow-plan-review
    ├── 验证输入门禁
    ├── 重建决策追踪映射
    ├── 报告并闭环修正问题
    └── 通过后自动调用 flow-implement
```

### 核心流程与状态

```text
已确认决策源 + design.md + task.md
→ 临时拆分决策 D1...Dn
→ 决策到设计正向检查
→ 设计到任务正向检查
→ 任务到设计反向检查
→ 无问题：输出摘要并进入实现
→ 有问题：批量报告并等待确认
→ 确认修正：修改原文档并重新完整检查
```

### 审查契约

- 决策源可以是 `flow-brainstorm` 的已确认决策摘要，也可以是用户直接提供并确认的完整需求。
- 必须同时存在决策源、`design.md` 和同目录 `task.md`；任一缺失即停止，不执行降级审查。
- 决策仅在审查过程中临时编号为 `D1...Dn`，默认不将编号写回正式文档。
- 每项问题必须给出可核对的决策、设计、任务、项目文档或代码依据，并说明实际影响。
- 仅在核实现状冲突时读取直接相关的代码、项目规则、功能文档或 ADR。

## 功能点

#### F1：验证审查前置条件

- 存在已确认决策源、`design.md` 和 `task.md` → 开始审查。
- 任一前置条件缺失 → 说明缺失项并停止，不以 `design.md` 代替原始决策源。
- 输入属于未经过 plans 的 bugfix → 判定不适用，不强行生成追踪映射。

#### F2：建立三向追踪映射

- 原始决策 → 检查 `design.md` 是否完整覆盖且未曲解。
- `design.md` 功能点与关键边界 → 检查 `task.md` 是否具有可执行、可验证的覆盖。
- `task.md` 每项任务 → 反查设计依据，识别新增业务规则、范围或未授权重构。
- 影响参与者、对象、状态或责任边界的术语存在多种合理解释 → 无法从决策源确定唯一含义时列为阻塞。
- 关键规则可能产生两种合理结果 → 使用具体场景反证；结果未定义时列为阻塞，不穷举低风险场景。
- 追踪完整且无矛盾 → 只输出已检查决策数量和通过摘要，不展开完整矩阵。

#### F3：报告有证据的问题

- 发现决策断链、术语歧义、场景结果未定义、文档矛盾、任务越界、必要决策缺失或不可执行计划 → 列为“阻塞”。
- 发现具有明确维护或验证风险但不影响正确实施的问题 → 列为“建议”。
- 只有措辞偏好且无法说明实际影响 → 不报告。
- 发现问题 → 展开受影响的“决策 → 设计 → 任务”链路、影响和推荐修改。

#### F4：确认后修正计划

- 多个问题 → 一次批量展示，允许用户全部采用或按编号处理。
- 用户确认文档修正 → 只修改 `design.md` 和 `task.md` 中对应内容，然后重新执行完整追踪检查。
- 问题需要新增或改变业务决策 → 返回 `flow-brainstorm`，不得自行补充决策。
- 阻塞项未解决 → 停止，不进入实现。
- 建议项被用户明确跳过且无阻塞项 → 允许审查通过。

#### F5：通过后自动实施

- 审查首次通过或修正后通过 → 自动调用 `flow-implement`。
- 用户明确要求停在计划阶段 → 不自动实施。

## 异常与边界

| 场景 | 处理 |
| --- | --- |
| 当前对话不存在可确认的原始决策源 | 停止并返回上游，不做局部一致性审查 |
| 设计与现有代码冲突 | 提供具体代码依据；若涉及业务方向则返回 brainstorm |
| 任务依赖不存在或成环 | 作为阻塞问题报告 |
| 同一问题可由现有项目事实回答 | 自行核验，不询问用户 |
| 只有非实质性的格式或措辞偏好 | 忽略，不制造建议项 |

## 风险与外部待确认

- 同一 agent 审查自身产物可能存在确认偏差；通过强制重建三向追踪映射和证据要求降低风险，但不宣称等同于独立审查。
- 无外部待确认事项。

## Out of Scope

- 不维护 `CONTEXT.md` 或 ADR。
- 不修改 `grill-with-docs`、`flow-review` 或 `flow-bugfix`。
- 不检查实现代码、测试覆盖结果、lint、typecheck 或 `git diff`。
- 不创建独立审查报告文件。
