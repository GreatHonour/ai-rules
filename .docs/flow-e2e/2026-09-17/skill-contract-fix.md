# flow-e2e 契约与命令修复

## 目标

- 类型：缺陷修复
- 复现：仅保留 `blocked` 任务后执行 `check` -> 报告写明存在阻塞，但命令返回成功且 `passed` 为 `true`；初始化包含未知依赖 -> 依赖被静默删除。
- 目标：统一技能说明、模板、脚本和测试；JSON 全程只使用 `depends`，阻塞不得判为通过，非法依赖不得静默放行，命令示例可直接用于 PowerShell 和 Bash。
- 根因：当前改动同时调整了任务 ID、依赖字段和完成语义，但文档、实现与测试没有共享同一契约，边界场景也缺少断言。
- 边界：`task_id` 继续使用来源任务编号，初始化输入和落盘 JSON 均使用 `depends`；不恢复旧版双 ID 结构，不新增命令或自动解析 Markdown。

## 历史依据

- 功能文档：`.docs/flow-e2e/2026-09-17/design.md`、`.docs/flow-e2e/2026-09-17/task-verification-fix.md`；用户确认 JSON 按当前版本执行。
- 代码历史：当前工作区同时存在已暂存旧契约和未暂存新契约，本次保留用户确认的新契约，不回退其他已有改动。

## 实现

- 统一任务模板与字段说明 -> 所有阶段只使用 `depends`。
- 加强依赖与汇总校验 -> 未知依赖、自依赖和未通过依赖不会被误执行，阻塞结果不会判为通过。
- 整理 CLI 参数与跨平台示例 -> 保留四个现有命令，明确退出码和错误处理。
- 补充回归测试 -> 锁定 JSON 结构、依赖门禁、阻塞汇总和参数解析行为。
- 根据复核反馈压缩技能正文 -> 删除面向人的 shell 教程，只保留 Agent 执行所需的规则、命令和环境工具路由。
- 保留用户提供的环境工具映射 -> PC/H5、微信开发者工具、移动端和视觉对比分别使用既定工具。
- 增加工具兜底边界 -> 用户提供的工具均不可用或能力不足时，才建议替代工具并等待用户确认，不自行切换或安装。
- 精简状态读取 -> `init` 后复用输入任务和返回的 ID，不再读取整个状态 JSON；仅在恢复或状态不确定时按 ID 调用一次 `get`。
- 复用验证证据 -> 同一测试能覆盖多个任务时只执行一次，再分别持久化各任务结果。
- 收敛阻塞处理 -> 阻塞任务不测试；继续独立任务，没有可执行任务时再统一 `check` 并停止。

## 验证场景

- `depends` 包含未知 ID、自身 ID 或重复 ID -> `init` 失败且不生成任务文件。
- 前置任务为 `pending`、`failed` 或 `blocked` -> `get` 返回依赖信息，执行者不会将任务误判为可执行。
- 无 `pending` 但存在 `blocked` -> 生成报告，`passed=false`，CLI 退出码为 1。
- 合法任务全通过 -> 生成报告，CLI 退出码为 0。
- PowerShell 与 Bash 初始化示例 -> 不依赖易损的 `echo '[JSON]'` 引号拼接。
- 新初始化流程 -> 不读取完整 `e2e-task.json`，不对每个任务重复同一测试。
- 依赖失败或阻塞 -> 当前任务直接记录 `blocked`，不执行验证；没有独立任务时停止。
